## 一句话

老版研究"一个不可信的外部 agent **能被授予多少**权限、表达、记忆访问才安全"；
现在研究"主力 agent **拿了另一个 agent 给的数据**去做不可逆动作时，靠什么分辨真假"。
从**限制它能做什么**，变成**核对它说的对不对**。

## 保持不变的（大伞）

- 问题域：多 agent 系统中与不可信 agent 共事的安全边界。
- 原则：Utility ≠ Authority；External Output Is Data, Never Authority；No Ambient Authority。
- 纪律：协议/预注册先于运行、判分与预测冻结、dev / held-out 分离、结果不可事后修补。
- 上游环境：AgentDyn / AgentDojo 真实状态变更任务。

## 逐项对照

## 老版构件的去向

- **保留**：原则；dev/held-out 与冻结纪律；M0/M1 来源闸门（作为反面基线，实跑结果：攻击 0、正常任务也 0）；D0–D6 归因漏斗思路。
- **改造**：C6 "raw-evidence re-grounding" 从**记忆边界**迁到**动作边界**，成为 RQ5 的核验膜；老 RQ4 "artifact 核验 < 原始证据"以动作版回答。
- **降级 / 放弃**：A0–A5 阶梯（E 固定为 A0）；R0–R4 表达阶梯（值只有一个槽位，收窄表达无意义）；老 RQ2 ContractNLI 降为附录（正交证据）；老 RQ3 记忆晋升列为 future work；三层权限试跑的 high-tier 20/20 为 harness 代写，只作工程收据。

## 为什么改

老版三层权限实验中，高档攻击全部由 E 自己执行（harness 代写），证明不了"H 被诱导"；中低档攻击全为 0。也就是说，**风险不在 E 有多少权限，而在 H 把 E 的话当真。** 把 E 的权限压到零后攻击仍约 90%，正是老版 Path A 的实证版本。

## 新的 RQ 体系（详见实验工作区 `proposal/PROPOSAL_v2.md`）

RQ1 现象（陈述 vs 指令）→ RQ2 为什么（核验通道）→ RQ5 解法（核验膜及其消融）→ RQ3 过程 → RQ4 多模型 → RQ6 自适应攻击 → RQ8 自适应核验（信任账本，把老版的"条件信任"思想接回来）。
