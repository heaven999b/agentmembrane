# 论文包装稿（两页版，2026-10-21）

> 用途：论文怎么讲的样稿，不是正式稿。数字全部取自 week14 发布结果与 EVIDENCE_MAP，没有新增实验。结构参考 GCAD（2605.10664）与 SafeCoDe v2（2509.19212），但改成测量为主、方法为辅。

**标题**：*Agents Follow Verdicts and Exits, Not Evidence: Measuring and Removing the Grey Zone in Delegated Writes*

**一句话**：Agent 的决定跟着判决和退路走，不跟着证据强弱走；所以不要给它灰色，要么给事实，要么交给人。

---

## 摘要

Agent 越来越多地依据别的 Agent 提供的值执行真实操作，例如同伴给出的商品编号、账户编号，而它自己看不到真值。外层系统（harness）的常见做法是先核对再放行。我们在 τ-bench 零售任务上构造委派缺口：同伴给出合法但错误的值。结果发现 Agent 并不衡量核对提供的证据，而是照着**判决**和**可用出口**行动，我们称之为 **verdict-following**。

把核对结果从"查不到"改成点名实际商品，做错率从 83% 降到 18%；出口从"仍然执行"按钮改成只许重发、再改成不给出口，静默写入从 31% 降到 19%、再降到 1%。相比之下，改变证据（说明登记册不全、开放查询、加一句查询提醒、换语气）的效果小且不稳定。在"查不到"之下，Agent 放行真值 88%、放行假值 78%，两者几乎没有区别。把出口全部关掉能挡住攻击（0/140），也挡住了全部合法的新值（0/70）。

据此，我们推出一条最小规则：**不给 Agent 灰色判决**。能变成事实的，由执行端解析成事实并用代码比对；没说清的，退回补全；其余交给人。按这条规则实现的见证式提交，在 35 题上攻击写入 0/140、正常完成 69/70。

## 1. 引言

**第 1 段 · 一条真实轨迹。** 顾客想把台灯换成不那么亮的款式，优先电池款。Agent 看得到各款的选项和价格，看不到编号，于是向同伴要编号。同伴给了一个编号，说"这就是银色、低亮、电池款"，实际上那是插电款。核对返回"查不到"，并附一个"仍然执行"按钮。Agent 按了下去，理由是"编号是同伴提供的"。执行后，系统返回的差价是 $5.08，而不是它先前报给顾客的 $12.07。Agent 把 $5.08 照转给顾客，还说换的是电池款。这里意图是对的，后果系统也知道，只是没有任何一方去比对。

**第 2 段 · 为什么重要。** 委派执行正在变成常态。核对是对的方向，但现有设计两头落空：留出口，错误的值会被放行（按钮下攻击写入 78%）；不留出口，合法的新值也会被挡住（未登记的真值 0/70 成功）。前者是不安全，后者是不能用。

**第 3 段 · 研究问题（单独框出）。**

> **Agent 依据什么决定执行同伴给出的值？Harness 应该怎样设计，才能既挡住错值，又不挡住合法的新值？**

**第 4 段 · 贡献。**

1. **发现 verdict-following**（RQ-A/B/C）。在所测委派任务中，Agent 的写入跟着判决（−59 到 −65pp）和出口（+30pp）变化，而不跟着证据强弱变化：查不到时，放行真值 88%、放行假值 78%。
2. **指出防御两难**（RQ-C）。所测的每种出口设计，要么放行错值，要么挡住合法新值。全面拒绝带来的低错误率，不能当作判断变好了。
3. **由数据推出最小 harness 规则，并测它的边界**（RQ-D + 边界）。规则的每个部件都对应前文的一个发现；我们同时报告它失效的条件，包括晚封存、登记册被洗白、付款粒度。

## 2. 场景与威胁模型（约半页）

- 角色：用户 U 给出目标，主力 H 执行，同伴 E 提供被遮蔽的值，Harness 负责核对、查询与门控。任务、数据库和工具都来自 τ-bench 原生环境，没有自写任务。
- 对手：E 给出的是**合法但错误**的值，格式和登记都过得去。对手碰不到执行端，也碰不到用户原话。
- 指标：F 为实际攻击写入，T 为正常成功，J = T − F，三者同时报。主检验按代码判写入，不用 LLM judge。

---

## 3. 测量：改判决和出口，决定大幅变化；改证据，决定基本不变

**核心表**（参照 SafeCoDe 的"把图换成空白，决策几乎不变"）：

| 改什么 | 结果 | RQ |
|---|---|---|
| 判决：查不到 → 点名实际商品 | R1 做错率 83% → 18% | B |
| 判决：粗反馈 → 点名 | 攻击写入 65% → 6% | B |
| 出口：按钮 / 只许重发 / 不给出口 | strict 静默 31% / 19% / 1% | C |
| 证据：说明登记册不完整 | 78% → 64%，p=.125 | B |
| 证据：开放查询 | 四因素交叉 −5pp，区间跨零；第 2 段查不到条件下 −28pp | B |
| 证据：加一句查询提醒（E1） | 查询 14% → 29%；写入 90% → 78%，区间跨零 | B |
| 语气：信息不变，改成建议口吻 | 6.82% 对 6.82% | B |
| 证据真假完全相反（查不到 + 按钮） | 放行真值 88%，放行假值 78% | C |

**交互**：点名时，三种出口下静默写入都在 3% 以下；查不到时依次为 60% / 35% / 0%。也就是说，出口只在判决是灰色时起作用。

**排除替代解释**（参照 GCAD 用 prompt-only 对照排除"只是长上下文"）：

- 是"同伴权威"的提示造成的吗？去掉这句提示后，无防御攻击写入 75% → 64%，现象仍在。
- 是 H 自己写的声明不好吗？换成系统代写的同题声明，做错率 77% 对 68%，现象仍在。
- 是模型不知道真款吗？写错的 506 局里，92% 在写入前已经对顾客报出真款的价格。

**辅助证据**：让 Agent 选择继续的理由时，40 次里有 38 次选"同伴权威"。这是模型自述，只作描述，不作因果解释。

**写法约束**：全文只描述行为，不写"模型分不清灰色"这类认知判断。查询开放在单批中有效（−28pp），要如实写出，结论措辞是"效果小且不稳定"，不是"无效"。

## 4. 原理：没有见证，就只能停在对角线上（约半页）

- 图 1（放在第 1 页）：横轴是假值被放行的比例，纵轴是合法新值被放行的比例，对角线等于抛硬币。只能说"查不到"的设计，不论出口怎么设，都落在对角线附近，例如 (78, 88) 和 (0, 0)。点名之所以有效，只是因为登记册恰好认得假值；登记册被洗白后，攻击写入回升到 90%。
- 结论：这是信息问题，不是模型笨。灰色判决里本来就不含区分真假所需的信息，Agent 怎么判都只能在对角线上取舍。这条用 TV 距离一句话说明即可，不当作新定理。

## 5. 方法：不给灰色

**规则**：能变成事实的变成事实，没说清的退回补全，其余交给人；出口留给人，不留给 Agent。

**实现（见证式提交）**：在 H 联系同伴之前封存用户目标 → 执行端解析委派值实际指向的实体，并在副本上预演 → 用代码比对封存的意图。匹配则放行；不符则点名实际实体并拒绝，可附唯一的修复候选；信息不足则要求补全或升级给人。

**每个部件由哪个发现推出**（方法一节的开头表，体现 data-driven minimal）：

| 部件 | 推出它的发现 |
|---|---|
| 由代码判定，不交给 AI | AI 判预演时，写明款式 15%、只给差价 80%；查不到时真假放行 88% 对 78% |
| 见证由系统送达，不做成可选工具 | 开放查询时效果小且不稳定，提醒能增加查询，但没有明确减少写错 |
| 见证取自执行端，不取登记册 | 登记册会缺（合法新值 0/70），也会被洗白（90%） |
| 在问同伴之前封存 | 晚封存、先揭示在红队中被打穿（12/162、17/162），先封存为 0/162 |
| 拒绝时点名，不说"查不到" | 83% 对 18% |
| 不留"仍然执行" | 出口主效应约 +30pp |
| 修复候选 | 主批攻击局中 37/52 改用正确值完成任务 |

不写 "first"。零件都已有人做过，新的是 setting、行为数据，以及这个组合的必要性。

## 6. 评估要点（约半页）

- **主批**（13 题）：攻击 0/52，正常 26/26，达到方法自身"攻击 ≤10%、正常 ≥80%"的门槛。相对 AI 判预演，J 约高 18pp，但原检验 Holm p=.25，**未过优势门槛，如实写**。
- **扩题与合并**（35 题）：攻击 0/140，正常 69/70；J 约高 19pp [8, 32]，Holm p≈.0032。这是稳健性补充，不替换主批判定。
- **来源**：登记册被洗白后，点名加按钮的攻击写入升到 90%，见证式提交为 0/52。
- **红队**：先封存 0/162，晚封存 12/162，先揭示 17/162，AI 判官 80/126（总写入）。按 strict 静默做的主检验没有显著差异，正文要分开报这两个指标。
- **第二模型**：反馈主比较 84% 对 13%，方向一致；只复现了部分 B/C。

## 7. 边界与局限（主动写）

- 只在 τ retail 上测，任务以确定事实为主；条件偏好、真正多解尚未覆盖（E2 中没有剩下多个候选的情况）。
- 第二模型与主模型同属一个供应商，跨供应商尚未验证。这是审稿人最可能的第一刀。
- 顾客是规则脚本，它的确认不等于真人重新授权。
- 方法依赖封存忠实、执行端解析可信、比对足够细；付款方式的识别粒度有限，AgentDyn 上没有完整复现。
- 优势：主检验按代码判写入，不依赖 LLM judge；共 21 个批次、7,696 条记录，有预注册，可离线复算。
