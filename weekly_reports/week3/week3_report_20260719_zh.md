> **怎么读**:每节先一句【做了啥+结果】。术语查下表。

| 术语 | 一句话人话 |
|---|---|
| **固化算子** | AI 后台"整理记忆"的动作。append=只追加不改旧的;summary=真把旧记忆重写成摘要 |
| **retrieval / top-k** | 回答时只调出最相关的 k 条记忆,不是全库塞给 AI |

## 1. 先自我拆解:上周的结论错在哪?(6 个共性根因)

| 根因 | 毛病 | 后果 |
|---|---|---|
| **R1 没有真正的固化算子** | 两线都只 `pool.append`,从不重写旧记忆 | PairGain 测的正是"不整理"这个对照组 → 结论近乎同义反复 |
| **R2 没有检索** | 官方 static 路径把整库塞进 prompt | 污染永远可见,效应被理想化放大 |
| **R3 全库平均稀释** | 信号在整个记忆库上取平均 | **实测:追加 20 条无关记录,信号从 0.643 掉到 0.031(21 倍)** |
| **R4 未来≈现在** | 只 3 步、还反复用同 3 问 | 当前状态几乎决定下一步,预测空间≈0,且问题泄漏 |
| **R5 对照退化** | 对手指标几乎是常数;精修每例只 3 条后代 | 比较无效 / 门槛不可达 |
| **R6 分支不对齐** | 整条错误内容换成正确内容 | 长度/语体失配(WF 长度比 0.34)污染测量 |

**结论**:上周的结论是"仪器"问题不是"理论"问题。

| 修复 | 做法 | 自证 |

## 3. dev smoke + 两个"我自己的错误"被现场抓到

> **一句话**:小规模真跑,机器全对;但真跑评估时**接连抓出两个我自己犯的构念错误**——这正是 dev/smoke 的意义:**在花大钱确证之前把仪器修对。**

**机器体检全过**:真算子在真 API 上确实重写旧状态、检索只喂 top-5、分支对齐 0 失败、无崩溃。

### 3.1 错误一:主测量结构性失效
真跑 NLI 时发现,我原本冻结的主测量 `source_only` 在真数据上**信号恒定 → 预测量 G 恒为 0**:它只测源头,而源头改对后不再变,固化的动态全在**摘要**里被它排除了(修 R3 时矫枉过正)。**若照此确证会得到假的"没信号"。** 改为 `consolidated_state`(源头+摘要),6/6 恢复变化。后又发现它在 append 下结构性为零会让"算子有效/无效"对比变成**循环论证**,再改为 **`carrier_matched`**(给两算子同定义的可比载体)。

### 3.2 错误二:检索挤出混杂(把主终点换掉了)
查真实检索日志发现:**d3 池更大 → 被纠正的正确记录被后代挤出 top-k**(污染臂纠正源召回 1/3~2/3,对照臂 3/3),效应量随**被挤槽位数**走,而非随"污染是否被固化携带"走。→ 朴素的 `d3−d0` **把"语义污染"和"检索挤出"混在了一起**。

**（这也撤回了 dev smoke 早期"d3−d0 残留存活=第一个反证"那句话——那个数是被混杂的。）**

**修正**:主终点从 `d3−d0` 改成 **残留分解**:

| 量 | 定义 | dev 预览(n=2,描述性) |
|---|---|---|
| **semantic_residual** | 污染d3 − 安全d3(**同池大小、同检索结构**,控住挤出) | **+0.44** [0.33,0.56] |
| **displacement_effect** | 良性体积 − d0(**纯挤出/体积**) | +0.06 [−0.11,0.22]（小、CI 含 0） |
| 合成量 d3−d0 | — | +0.48（≈语义+挤出 0.50 ✓ 自洽） |

**方向性读法(不是判定)**:在 summary 上残留**主要是语义污染,挤出只占零头**——支持原 headline。但 n=2、且 summary 只挤 1 槽,append 挤 3 槽可能不同 → **确证的 30 例五臂会分辨清楚。**

## 4. 两个执行/口径纠正(如实记下)

- **"慢"的真相**:之前判"并发限流拖慢"其实**主因是笔记本睡眠**(合盖挂起进程,醒了继续;单发 API 实测仅 1.2s)。真相是机器醒着吞吐正常,长任务跨睡眠周期墙钟拉长但**断点续跑不会死**。教训仍是别多路并发,但主因是 sleep。
- **评价标准 git 实证**:逐条核对官方 benchmark——官方仓库是公开的 `github.com/xiewwee11/MemEvoBench`;**QA 数据 7 文件未改、官方 judge rubric 零改动(diff 只加 sys.path)、我方代码无自造安全 rubric**(unsafe 全走官方 judge)。**唯一口径偏离**:主 judge 用 gpt-4.1-mini 而非官方默认 gpt-4o(judge2=gpt-4o 做 AND 闸门缓解),已声明;WF 侧官方文件有改动未审计(WF 是次要线)。

## 6. 当前状态:确证正在跑

> **一句话**:你已授权,**30 个未见 QA case × 五臂 × {真算子, 追加对照} 的确证正在后台串行运行**;它会给出 semantic_residual 的确证 CI,决定 Paper B 的 headline(或判负)。

**三种可能结局(都会如实写进报告,正负都认)**:
1. **semantic_residual 显著 > 0** → "污染在固化状态里语义持久化,改源不足以闭环"(原设想成立)
2. **语义≈0、挤出主导** → headline 换成"**固化产物挤占检索预算,导致纠正无法被召回**"(更可操作的机制发现)
3. **两者都≈0** → v1 的 +0.70 被两个对照吃掉 → **Paper B 核心塌,诚实判负**

### 6.1 ✅ CHIR/RQ3 确证结果(summary_rewrite, 未见 30 QA case, 冻结判据) = **GO**

| 指标 | 值 | 判定 |
|---|---|---|
| **semantic_residual**(主终点, d3−safe, 控住挤出+轨迹) | **+0.170, 95%CI [0.085, 0.270]** | **CI>0 ✓** |
| **AND 双 judge**(更严) | **+0.178, CI [0.093, 0.278]** | 扛住 ✓ |
| displacement_effect(纯检索挤出) | +0.011, CI 含 0 | 无挤出混杂 ✓ |
| 算子退化率(no-op) | **0.2%** | 真算子(99.8% 真重写状态)✓ |

臂水位: contam_d3 0.311 / safe_d3 0.141 / contam_d0 0.070 / benign_vol 0.081 / full_closure 0.056。

**这是本项目第一个真正意义上的确证阳性**: 改对源头后污染在固化状态里留下的语义残留**是真的**, 同时扛住真固化算子(非追加)、真 top-k 检索、检索挤出控制、固化轨迹控制、AND 双 judge。**"source correction ≠ correction closure" 在严格控制下成立。**

**诚实边界**: +0.17 **比 v1 的 +0.70 小很多**——因为剥掉了检索挤出、固化轨迹、体积三个混杂。这是**真实但温和**的效应, 不是原来被放大的大数字。**还差最后一道坎**: k 敏感性(k=3/10)——效应会不会只在 k=5 出现。append operator-off 对照、PairGain(RQ1+RQ2)、多 seed 仍在队列。

**下一步**: append 对照(跑中) → k∈{3,10} 敏感性 → PairGain 确证 → 全部(正/负)回填。

**还没解决、需资源的**(命令/动作已备好):k 敏感性/多 seed/第二模型(需 API)、稠密检索(需批准下载)、引用真伪(只能作者核验)。结构性救不了的(RQ2/RQ4/NLI 句级盲区/full_closure oracle 上界)已写成论文 limitation。
