# Week 17 · 只核对 + agent 轨迹:干净对比

发布:2026-11-11。

本周把方法从"平台能看目录、自己挑款"改成**只核对**:平台不给编号,只核对 H 提交的每一次写入。核对要用的事实,来自 H 自己查到、由平台记进**轨迹**的结果。

- 先用 6 个开发批把方法一步步搭起来(out_bl7–bl12)。
- 再用 out_bl13 和外部方法同批跑了一次参照。
- 最后跑了一批**干净对比**(out_bl14):四格,每两格之间只差一项。

## 结果一览(out_bl14,42 道题 × 4 格,同一批,1,112 局,gpt-5.6-luna)

| 格 | 只差什么 | 正常完成 T | 错值放行(易 / 难) | 综合分 J |
|---|---|---|---|---|
| V5S2 | 旧规则:没提的属性一律不许变 | 66% | 0 / 0 | +66 |
| **V5S3** | 新规则 K1;事实来自轨迹 | **72%** | 0 / 0 | **+72** |
| V5S3n | 同 V5S3,但平台不给事实 | 30% | 0 / 0 | +30 |
| V5S3c | 同 V5S3,但事实直接来自商店 | 74% | 0 / 0 | +74 |

| 对比(只差一项) | 差值 [95% 区间] | 单侧 p | 判定 |
|---|---|---|---|
| **轨迹里的事实 vs 不给事实** | **+42 [+26, +58]** | **0.00004** | **成立** |
| 新规则 K1 vs 旧规则 | +6 [−4, +16] | 0.24 | 方向对,不显著 |
| 商店事实 vs 轨迹事实 | +2 [−5, +10] | 只描述 | 区间太宽,不能说"轨迹够用" |

- **正常完成 T**:同伴给了正确编号时,任务按 τ 官方标准办成的比例。
- **错值放行**:同伴给了错编号时,错编号真被写进订单的比例。
- **综合分** = T − 易攻击错值放行率(百分点)。
- **干净对比** = 两格只差一个开关;同一批、同样的题、局数和种子;开跑前预注册,批中不改代码。

**一眼结论**

1. 平台能用轨迹里 H 自己查到的事实时,能下"对 / 不对"的判决;不给事实时,只能判"定不下来",完成率低 42 个百分点。这一项是干净对比,而且显著。
2. 本周只改的一条规则(K1)修好了它针对的 3 道题,但总体 +6 不显著。
3. 四格错值放行都是 0。
4. 离"平台能看目录、直接挑款"的 NEW5S(92%,跨批参照)还差约 18 个百分点。剩下的失败集中在"读顾客话只读一次"和"定不下来 → 问顾客"这两处。
5. 只核对的代价:被攻击时用真值办成是 0%。
