## C1 是怎么拉开的

- 不给事实时,凡是要靠事实判的,一律"定不下来"。平台不叫 agent 去查,而是让 agent 问顾客,顾客又答不到点上。
  - 例:rt1 r0。V5S3 一次 MATCH,办成;V5S3n 判"定不下来",写入被拦,没办成。
  - rt1、rt58、rt29、rt70、rt74、rt89、rt96、rt106 等题,V5S3n 都是 0/4,其他格都是 4/4。
- **反例 rt23**:V5S3n 3/4,其他格 0–1/4。
  - 顾客说烤架要换成"和已收到那台同一类型"。读顾客话时只读成"类型 = 炭烤",没读成整款相同,于是尺寸、配置算作"没提"。
  - 有事实时,K1 发现有便携款可以保持这两项,就拒了正确款(中号带烤叉),放行了错的那款。按 V5S2 的规则,同样的读法也会拒正确款。
  - 不给事实时判"定不下来",H 去问顾客,顾客说清楚了,反而办成。
  - 也就是说,读错顾客话的时候,有事实反而会按错的读法放行。错的源头在读顾客话那一步。

## 这批说明了什么(对回问题)

1. **轨迹那一层是必要的**:
   - 平台不靠事实,只读顾客话,办成率是 30%;用轨迹里 agent 自己查到的事实,升到 72%。
   - 这次只差这一项,所以 +42pp 可以归到轨迹上。
2. **轨迹和平台自己看商店的差距不大**:+2pp,但区间 [−5, +10] 太宽,按预注册不能下"够用"的结论。
3. **K1 修好了它要修的那类错**:rt6、rt94、rt95,原来 0/4,现在 3–4/4。
   - 但总分 +6pp 不显著。剩下的失败主要来自两个地方:
     - 读顾客话本身的随机性,每局只读一次;
     - "定不下来 → 问顾客"这条退路,顾客常常答不到点上。
4. **和 out_bl13 的 NEW5S(92%)相比(跨批,只作描述)**:V5S3c 是 74%,还差 18pp。
   - V5S3c 和 NEW5S 在"事实"和"没提的属性"两项上已经一样。
   - 剩下的差别是流程:NEW5S 由平台读完顾客话直接挑出款式,编译提示也不同;我们是让 agent 提议,平台核对,定不下来就让 agent 去问顾客。
   - 这 18pp 归到哪一处,要再拆一批才知道。

## 下一步候选(都要用户点头)

- "定不下来 → 问顾客"这条退路:改成把候选列给顾客选,或在候选唯一时直接放行。按控制变量,所有格一起改。
- 读顾客话改成多次采样再投票,降低单次读错的随机性。这会改所有格共用的部分,要单独一批测。
- 同款换同款的写入应该拦下(rt107 V5S3 r0:H 把靴子换成了同一件商品,平台放行了)。这是 out_bl12 记下的老问题。
