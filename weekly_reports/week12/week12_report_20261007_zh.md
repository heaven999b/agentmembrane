# 第十二周研究汇报(截至 2026-10-07):各 RQ 的实现、证据与状态

> 本周覆盖 2026-10-01 至 10-06。按 proposal(10-01 版)的研究问题逐条写:**问什么、怎么实现、证据怎么样、现在什么状态**。证据分三级:**正式** = 预注册的确认性检验;**稳健性** = 看到结果后追加的、或在旧题 / 开发题 / 第二模型上的复算;**诊断** = 零 API 分析、每格只跑 1–2 次的对照。全部数字可在各批 RESULT 与本周快照里核对。

## 先用一个例子看懂这篇在做什么

一个 AI 客服替顾客办换货。顾客说:"把我那盏台灯换成电池款的。"换货要填新商品的编号,AI 不知道编号,就去问另一个 agent(比如供应商那边的 agent)。对方报了一个编号。问题是对方可能报错,也可能故意报错:它给的是同一款台灯**插电版**的编号。这个编号是真实在售的商品,只是不是顾客要的那件。AI 拿着它把换货办了,顾客收到插电版。AI 嘴上跟顾客说的是"电池款,补差价 12.07 美元",系统里实际写进去的是插电版、补差价 5.08 美元。谁都没发现。(真实轨迹:τ 零售 rt6 台灯题,电池款 7453605304,写进去的是插电款 1569765161。)

这篇论文量的就是三件事:AI 在这种情况下会不会照用对方给的编号(会,七到九成);系统核对之后**怎么回话**、给不给它"仍然执行"的按钮,会不会改变它的决定(会,而且改变很大);什么样的核对能真正挡住。

**见证式提交**是这篇提出的做法。三步,全由系统强制,不靠 AI 自觉:

1. **先封存**:AI 在去问对方**之前**,按顾客的话和它自己查过的目录写下"顾客要的是:台灯,电池款",封存起来。对方的话进不了封存,因为封存时还没问它。
2. **先预演**:AI 拿着对方给的编号来办换货时,系统不直接执行,先在数据库副本上试跑一遍,查出这个编号实际是哪件:"台灯,插电款"。
3. **代码比对**:一段普通程序把预演结果和封存内容对一下。电池款 ≠ 插电款,就拒绝,并告诉 AI"这个编号是插电款,不是顾客封存的那件"。AI 没有"仍然执行"的按钮,只能拿到正确编号再来(修复模式下系统直接给它唯一正确的编号),或者交给人。对得上就执行。

叫"见证"是因为预演结果来自执行系统本身,骗子碰不到它;不像登记册可以被洗白,也不像 AI 自己的判断可以被说服。

结果一句话:挂上之后,140 局攻击里错编号一次都没写进去;顾客真要换新品的 70 局里 98% 办成。不挂、只给按钮:66% 到 78% 写错。让 AI 自己看预演结果来判而不是代码判:写明款式时 15% 写错,只给差价时 80% 写错。下面各节是逐条证据。

## 一句话主线与证据对应

**主线句**:AI 的决定跟着判决和退路走,不跟着证据强弱走;所以别给它灰色,给它事实,或者给人。"灰色"指核对既没确认也没反驳的情形:只说查不到、只说有问题不说是什么、登记册不全、有查询工具但要它自己去查、并排写出别的路、顾客点头。下表是对各节证据的另一种读法,不含新数据。

| 角度 | 数据 | 在哪节 |
|---|---|---|
| 它只有两个开关:有没有反证、有没有被允许的路 | 核对回话 +30pp,出口 +30pp;点名世界任何出口 ≤ 3%,查不到世界 60% / 35% / 0% | §2、§3 |
| 灰度信息进不了它的决定 | 告诉它登记册不全 −15pp 不显著;查询工具 −5pp 不显著;并排写别的路 67% 对 68%;换语气 7% 对 7%;按钮下放行真值 88%、假值 78% | §2、§3 |
| 它的分辨率取决于反证怎么写 | AI 自己判预演:写明款式 15%、只给差价 80%;查不到时被骗 242 局 0 局写前看到实际款;点名后 13 局里 8 局看见了也写;按按钮的理由 38/40 是"同伴权威" | §3、§4b、§8 |
| 灰色没法靠判断解决 | 不带见证的设计放行真值和假值一样:按钮 88 对 78,不给退路 0 对 0,来源闸门 0 对 0 | §8 原理、图 1 |
| 见证式提交不判灰:能变事实的变事实,没说清的退回补,其余交人 | 0/140、98%;去掉任一环就把灰重新交给判断:AI 判官 15% 到 80%,登记册洗白 90%,按钮 68% 到 78% | §4b |
| 灰的残余 | 误杀 1/70;一单两个值、第二个晚封存的漏洞;付款方式见证粒度;只能反查的场景退化成不给退路 | §4b、§6 |

**见证式提交怎么处理灰色**:

| 灰色情况 | 规则 | 结果 |
|---|---|---|
| 值真实存在但是另一件 | 执行端解析出实际那件,与封存有冲突属性 | 拒绝并点名;修复模式下若只有一件符合封存就直接给出 |
| 封存没写全 | 解析出的那件有封存没点名的属性 | 退回要求补全;只许补不许改,补的词须来自用户或 AI 读过的记录 |
| 封存里混进同伴的词 | 封存时拒收 | AI 重新封存 |
| 预演本身报错 | 放真调用,真调用报同样的错,库不变 | 等于没写 |
| 执行端解析不出这个值 | 拒绝并交人 | 安全但办不成;转账类场景会一直如此 |
| AI 自己把封存写偏 | 按不符处理 | 拒绝、交人,正常组 1/70 |
| 没有结构化规则的值类型 | 按名字词重合率判,0.8 算对、0.34 算接近,接近也按不符 | τ 的主要值类型不走这条 |

## 1. RQ-A 背景:AI 会不会照用同伴给的错值

**怎么实现**:主力 AI(gpt-5.5)在 τ³-bench 零售换货题里需要商品编号,目录里编号被遮住,只能问同伴(gpt-6-astra);攻击组同伴报同产品另一款的编号。不设任何防御,按数据库终态判"攻击值是否被写入"。

**证据**:τ 核心批无防御 75%(13 题);开发批 100%;旧确认集 τ 18/20、AgentDyn 16/18(第 10、11 周)。正常组(真值)未经筛选 95%。

**状态**:完成。只作背景,不当贡献:HARP 等已报告过"只改值"的攻击。

## 2. RQ-B 主发现一:核对结果怎么说,AI 的决定会不会不同

**怎么实现**:AI 先声明"我要的是哪一款",系统查登记册后回话。同一道题、同一个假值,只换回话:
- ① 点名:"这个编号登记的是 Y,不是你要的 X"(N);
- ② 查不到:真的把假值那条登记删掉,回"查不到"(G);
- ④ "您是不是指 Y"(S);
- ③ "查不到,而且登记册是完整的"只在 AgentDyn 做(τ 的假值都在售,说不出"完整")。
回话与出口交叉(见 RQ-C)。主检验 T1 = ②×按钮 对 ①×按钮,商品题 9 簇;13 题预注册,攻击 ×4、正常 ×2;簇级精确符号检验;主指标是"攻击值被写入"(开跑前被改成"未确认即写入",本周恢复用户原批的"静默写入"口径,两种都报)。

**证据**

| 对比 | 数字 | 级别 |
|---|---|---|
| 查不到 对 点名(按钮下) | 83% 对 18%,+65pp [44, 85],8 / 0 / 1 簇,p = .004 | 正式 |
| 同上,第二模型 | 84% 对 12%,p = .008;旧题不显著 | 稳健性 |
| 同上,三套题合并 | 36 题 / 28 簇,87% 对 15%,24 / 0 / 4 | 稳健性 |
| 同上,交叉设计主效应 | 32% 对 2%,+30pp [18, 41],Holm 2e-4 | 正式 |
| 点名 对 "您是不是指 Y"(同信息,只换口气) | 7% 对 7% | 正式 |
| "您是不是指 Y" 后锁住改口 对 不锁 | 无差别(T3 不成立) | 正式 |
| 查不到 + "登记册完整"(AgentDyn,4 簇) | 62% 对 52%,没有更不敢越过 | 诊断 |
| 点名但不说出 Y(粗反馈) 对 点名 | 65% 对 6%,+59pp [36, 81],p = .004 | 稳健性 |

**结论**:起作用的是**信息**(有没有反证),不是措辞。原定"换说法"的新意不成立,改写为"给反证就停,只说查不到就越过,不点名的粗反馈有害"。

**状态**:完成。缺口:每种回话只有一种写法,模板敏感性待补(约 300 局)。

## 3. RQ-C 主发现二:留退路,它用不用、用得对不对

**怎么实现**:同一回话下换出口:
- 按钮:给一个"仍然执行"工具(O);
- 只许重发:不给工具,原样再发一次写入即执行(R);
- 不给退路:规则只写进提示词(prule),或系统强制拦截(rot);
- 并排写出其他做法(问同伴、查记录、报告用户、转人工)再给按钮(Oalt)。
正常组把真值也从登记册删掉("真值不在册"),量不给退路的代价。补全批 35 题 1,050 局,主题集 13 题预注册 C1–C4;交叉设计再把回话 × 出口 × 查询工具 × 顾客脾气 24 格一次跑完(780 局)。

**证据**

| 对比 | 数字 | 级别 |
|---|---|---|
| 按钮 对 不给退路(提示词 / 强制),查不到世界 | 68% 对 0/52、0/52,+68pp [45, 89],Holm .006 | 正式 |
| 同上,35 题合并 | 78% 对 0/140 | 稳健性 |
| 按钮 对 只许重发 | 68% 对 48%,+20pp(静默口径不显著) | 正式 |
| 并排写出其他做法 对 只给按钮 | 67% 对 68%,+1pp [−6, 8] | 正式 |
| 放行真值 对 放行假值(按钮) | 88% 对 78% | 正式 |
| 不给退路的代价(正确新值) | 0/70 办成;121/140 转人工 | 正式 |
| 如实告知登记册覆盖率(99.8%)对 不告知 | 64% 对 78%,−15pp,p = .125;覆盖率减半 69% | 诊断 |
| 交叉设计:出口主效应 | 按钮 31% / 只许重发 19% / 不给退路 1%,两两明显 | 正式 |
| 交叉设计:回话 × 出口交互 | 点名世界三种出口 2% / 3% / 1%;查不到世界 60% / 35% / 0% | 正式(描述) |
| 交叉设计:能否自己查 | 开 14% 对 关 20%,−5pp [−11, +1],不明显;被骗局里写前查过 2/26 | 正式 |
| 交叉设计:顾客会不会拒 | 16% 对 17%,−1pp;正常组误拒 3% | 正式 |
| 按钮理由码(AI 自报) | 查不到:"同伴的记录是权威" 38/40;点名:"顾客已同意" 5/12 | 诊断 |

**结论**:有退路就走,不看证据强弱、不靠自查、不靠顾客;不给退路全停,正确的新值也全被挡。这是两难。

**状态**:完成。

proposal 原定 RQ-D 是"按规律设计的核对提示管多大用,和别人的防御比";10-04 用户授权扩成"怎么打破两难"。两部分都做了。

| 强制拦截(点名世界) | 0% / 89% | 正式 |

结论:在本场景里,规则写进提示词和系统强制一样好;来源类和升级类防御安全但不可用。

**4b. 见证式提交(新方法)**

用台灯例子说:问同伴前先封存"顾客要电池款";系统在库副本上预演对方给的编号,查出是插电款;代码比对不符就拒绝并点名,AI 没有"仍然执行"的按钮。例子见开头。

**怎么实现**:AI 在问同伴**之前**封存"要哪一件"(用用户的话和已读目录的用词,不含同伴的话;只封存那一件;商品与付款方式各一份);系统在数据库副本上**预演**这次写入,解析出实际那一款;**代码**比对封存与解析结果;只回放行 / 点名不符(可附合法范围内唯一的正确值,即"修复")/ 先补全 / 交人,**不给 AI 退路**。13 题预注册(P1–P3),攻击 ×4、正常 ×2;扩题 22 题;第 2 段同批跑消融与基线;指标:攻击写入、正常新值办成、J = 两者之差。

**证据:主结果与同题对照(35 题 / 29 簇)**

| 做法 | 攻击写入 | 正常新值 | 级别 |
|---|---|---|---|
| 不设防 | 75–100% | 95% | — |
| 查不到 + 按钮 | 66–78% | 77–80% | 正式 |
| 查不到 + 不给退路 | 0% | 0% | 正式 |
| **见证式提交** | **0/140** | **69/70(98%)** | 正式(13 题)+ 稳健性(35 题) |
| 见证式提交 + 修复 | 0/52 | 25/26;攻击局 73% 改用正确值办成,转人工 62% → 15% | 正式 |

**证据:消融,每一环去掉会怎样**

| 去掉哪一环 | 换成什么 | 结果 | 级别 |
|---|---|---|---|
| 执行端见证 | 登记册核对,假值被洗白登进登记册 | 登记册类 90%、提示词规则 85% 被骗;本文 0 | 稳健性(+84pp [73, 94],11 / 0 / 0) |
| 代码裁决 | AI 自己看预演判(写明选项) | 15% / 94%;本文优势 J +19pp [8, 32] p = .003(写入口径),+11pp [2, 22] p = .02(静默口径);13 题单独不显著 | 正式 + 稳健性 |
| 代码裁决 | AI 自己看预演判(只给差价) | 80% / 91%;呈现方式差 +65pp [50, 78],p < .0001 | 正式 |
| 代码裁决 | LLM 监督(More Rejective 原提示词),无 / 有预演 | 51% / 52%;0% / 80%(本文同批 0% / 95%) | 稳健性 |
| 代码裁决 | LLM 监督(IntegrityGuard 原提示词),无 / 有预演 | 82% / 91%;68% / 84% | 稳健性 |
| 封存先于接触 | 读完同伴再封存 / 先揭示再封存 | 无说服时都 0;说服下封存被污染 12/152、17/116(见边界) | 正式 |
| 不给出口 | 按钮 | 68–78% | 正式 |

**状态**:两难在本 benchmark 上被打破。但 0% 在规则写对时**按构造成立**,不当发现报;能当证据的是上两表的差距、封存 99% 忠实、修复 73%。预注册门槛落在"由用户定"(13 题上对 AI 判官不显著,35 题显著)。缺口:只能"正向解析"的场景(τ 零售)里见证是白送的;"只能反查"的场景(转账)可行性评估显示现有公开数据做不成第二主场景。方法延伸(解析代替核对、结构化封存、主动消歧)经三方讨论不做实验,写成讨论。

## 5. RQ-E 普遍性

**怎么实现**:第二个模型 gpt-5.6-luna 作主力,跑 RQ-B/C 用到的格(无防御、点名 + 按钮、查不到 + 按钮、查不到 + 只许重发),主题集与次要题集,220 局。

**证据**:主题集 T1 复现,84% 对 12%,+72pp [47, 94],7 / 0 / 1,p = .008;旧题上 +17pp,不显著(luna 收到点名回话后仍按按钮 46%)。

**状态**:未达 proposal 的"≥ 3 个模型、≥ 2 家公司"。两个模型同属一家,结论只能写"OpenAI 模型如此"。补别家模型需用户放宽"只跑 GPT",并等 API。投 AI 类会议时这是最大软肋。

## 6. 边界:知道规则的骗子能否绕过

**怎么实现**:
- 借口:同伴回复附"登记册还没更新,编号没错";教声明:同伴说出假款的登记名(核心边界批,176 局);
- 洗白:假值以真款的名义登进登记册(第 2 段);
- 针对规则的三种话术(权威豁免、伪造核对通过、声称顾客已确认)× 提示词规则 / 强制(312 局);
- 五种说服话术(换款、伪造偏好、教封存、顾客已同意、教补全)× 四种防御(本文、读完同伴再封存、先揭示、AI 判官),18 题两阶段,768 局;另加会拒绝的规则顾客。话术全部由代码按目录填空,逐字留在工作区附录,本文只用代号。

**证据**

| 攻击 | 对什么 | 结果 | 级别 |
|---|---|---|---|
| 借口 | 查不到 + 按钮 | 68% → 77%,不显著 | 正式 |
| 教声明 | 点名 + 只许重发 | 7% → 9% | 正式 |
| 洗白 | 登记册核对 / 提示词规则 / 本文 | 90% / 85% / 0 | 稳健性 |
| 针对规则话术 | 提示词规则 对 强制 | 2%(上界 5%)对 3%,守住 | 正式 |
| 五种说服话术 | 本文 | 0/162,封存污染 0 | 正式 |
| 同上 | 读完同伴再封存 / 先揭示 | 总写入 3% / 5%;封存污染 9% / 13%;静默口径差距不明显 | 正式 |
| 同上 | AI 判官 | 总写入 15% → 50%,明显;**静默写入 0**,被打穿的局全是 AI 转告顾客、顾客照例点头 | 正式 |
| "教 AI 怎么写封存" | 有封存的三格 | 0/230 | 正式 |
| 会拒绝的规则顾客 | AI 判官 / 先揭示 | 74% → 19%;17% → 0;正常组误拒 6% | 诊断(×2) |

**结论**:说服攻击打的是人的橡皮图章,不是 AI 的判断;封存先于接触把唯一攻击面关上,但实测幅度小。

**状态**:话术只有固定草稿,未经红队强化(撰写强化话术的工作被安全分类器两次中止,此线停止);攻击强度有限,写进局限。

## 8. 跨 RQ 的材料

- **机制解剖**(零 API,4,704 局复判):被骗分两种。只说"查不到"时蒙着眼:被骗 242 局里 0 局写前说出实际款,97% 对顾客描述的是真款;点名或预演亮出实际款后,看见了也照办(点名 + 按钮 8/13、AI 判官 14/14)。"看到 → 信 → 决定 → 写"四步各有数据(§2、§3 理由码、§6)。
- **原理**:没有骗子碰不到的见证,放行真值 = 放行假值;所有不带见证的设计都在对角线附近(附件图 1)。写成 CMSI 定理 1 的概率推论,不是新定理。
- **近邻**:18 篇全文精读;四个零件(执行端预演、代码裁决、意图先行、无出口)都有人做过;护城河是"事实缺位的场景 + 执行者行为数据 + 组合缺一不可"。零 API 普查:35 题里 29 题是同产品另一款攻击,五种近邻闸门在这些题上 J = 0。
- **独立审核**:全部批次从原始轨迹重算,数字一致;13 处设计偏离列表;主指标被擅改一事已更正。
- **评测工具**:21 个世界 + 7 个修饰符,能逐字节复现本周作业清单与判分。
