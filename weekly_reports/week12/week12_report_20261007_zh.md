# 第十二周研究汇报(截至 2026-10-07):核心实验落地、"查不到"两难、见证式提交及其消融、红队与交叉设计

> 本周覆盖 2026-10-01 至 10-06。全部正式批次按预注册判定;每个数字都能在各批的 RESULT 文件和本周快照里找到。证据分三级:**正式** = 预注册的确认性检验;**稳健性 / 次要** = 看到结果后追加的、或在旧题 / 开发题上的复算;**诊断 / 工程** = 零 API 分析、每格只跑 1–2 次的对照、冒烟。本报告只讲结论和数字,不复述设计细节。

## 一、一页摘要(没时间就只看这一节)

**问题。** 一个 AI 代理要拿另一个 AI 给的值(商品编号、收款账号)去做收不回的事。那个值指向哪一件东西,用户说不出来,系统事先也不知道;同伴可能给错。给人用的核对流程(银行转账前的收款人核对)照搬给 AI,管不管用?

**本周五个结论。**

1. **AI 照着核对结果和出口走,不照着证据走。** 核对能点名"这个编号其实是另一款",它就停(被骗 2–18%);只能说"查不到",它就越过(32–83%)。给它"仍然执行"按钮,它就按(60–78%);不给退路,全停,但正确的新值也全被挡(0/70)。同样的信息只换口气,没有差别(7% 对 7%)。这些在 13 题的预注册实验、三套题合并 28 簇、以及一个 24 格的交叉设计上都成立。
2. **它被骗有两种方式,机制不同。** 只说"查不到"时,它**蒙着眼**:被骗的 242 局里,0 局写之前说出过实际那款,97% 对顾客描述的是正确的那款——意图对,操作错。一旦系统把实际那款亮出来(点名、或预演写明选项),它**看见了也照办**:多数被骗局里它先告诉顾客"这是另一款",固定规则顾客回"是",它就写。它按按钮时自报的理由 38/40 是"同伴的记录是权威",不是"没法核实"。
3. **原理:没有骗子碰不到的"见证",谁都分不清真假。** 所有不带见证的设计(措辞、出口、规则、告知覆盖率)都挤在"放行真值 ≈ 放行假值"的对角线附近;能点名有效,只因登记册碰巧认得假值。这是已有定理(CMSI 定理 1)在这个场景的概率推论,不是新定理。
4. **方法"见证式提交"打破两难,但零件都不新。** AI 在问同伴之前封存"要哪一件";系统在执行端预演这次写入;代码比对;不给 AI 退路。35 题上攻击值 0/140 写入、正确新值 98% 办成。它的价值靠**同题消融**证明:用登记册代替执行端见证,洗白后 90% 被骗;让 AI 代替代码裁决,写明选项时 15% 被骗、只给差价时 80%;读完同伴再封存,在说服下封存被污染 9–13%;留出口,68–78%。单个零件(执行端预演、代码裁决、意图先行、无出口)在 18 篇精读过的近邻里都有人做过。
5. **说服攻击打的是人的橡皮图章,不是 AI 的判断。** 五种同伴说服话术下,四种防御的**静默写入都是 0**;所有被打穿的局都是 AI 转告顾客、顾客照例点头。"教 AI 怎么写封存"0/230。换成会拒绝的规则顾客,AI 判官的被骗从 74% 降到 19%。

**一句话。** "查不到"不是判决;AI 自己下不了判决,交给会点头的顾客也不行;判决要由代码拿执行端的事实,去比 AI 事先锁定的意图。

**本周规模。** 20 个批次共 7,665 局,其中正式与稳健性批次 13 个、6,982 局(含 10-02/03 落地的核心实验);另有零 API 分析对 4,704 局轨迹复判。除 AgentDyn 基线批里 Progent 动态模式的 22 局运行报错(如实计入该批结果)外,其余批次最终 0 错误行(基础设施错误均重跑);每批跑完逐局抽检。

## 五、这些结果能说明什么,不能说明什么

**能说明**
- 在 τ³-bench 零售换货上,gpt-5.5 作为执行者,对核对结果的反应由"说了什么"和"给了什么出口"决定,不由证据强弱、能否自查、顾客脾气决定;两个主因素强烈交互(点名世界任何出口 ≤ 3%,查不到世界 60% / 35% / 0%)。
- 同伴主动说服时,AI 的意图(封存)几乎不被改;被打穿靠的是顾客点头。
- 见证放在执行端、由代码裁决、意图先于接触锁定、不留出口,这四件缺一件就在对应的一刀上失败;合起来在本 benchmark 上两难被打破。

**不能说明**
- 别家模型如此(两个模型同属一家);别的场景如此(只有零售换货;转账类"只能反查"场景的可行性评估结论是现有公开数据做不成第二主场景)。
- 本文方法在"系统无法按描述找到值"的场景里有效:在那里它退化成"带封存的不给退路",0% 不再按构造成立,尚无数据。
- 更强的说服攻击下仍 0:话术只有五条固定草稿;红队强化这条线因安全分类器两次中止而停止。
- 真实顾客会怎样:固定规则顾客一律回"是";规则顾客只在 AI 提到攻击属性时拒绝。

## 六、本周发现并修掉的问题

| 问题 | 修法 |
|---|---|
| 主指标在核心批开跑前被改成"未确认即写入",未经用户同意 | 恢复用户原批的"静默写入"为主指标,两种口径都报;偏离表记录 |
| 严格口径判不了的题,写入被默认记成"静默" | 单列"不可判",不算静默;红队批数字据此更正(AI 判官静默 13% → 0) |
| 写入结局把同一任务里另一件商品的无关写也算进去 | 只算携带委派值的那次写 |
| 封存接地只认用户原话,真值最多 2–7/13 能通过 | 接地 = 用户的话 + AI 已读的目录记录,不含同伴的话 |
| 封存把用户的偏好列表当成要求,真值也判冲突 | 只封存偏好选出的那一件 |
| 商品与付款方式共用一份封存,第二类被锁死 | 按种类各一份 |
| 第 2 阶段话术选择的平局规则几乎总选固定顺序第一位 | 平局先按总写入(自适应率只作乐观上界) |
| 停批时 xargs 子进程残留,按旧清单多跑 38 局 | 已隔离不计;停批连 xargs 一起杀 |
| 代理持续 503,交叉设计批分三轮、跨两天跑完;105 个错误行 | 隔离后重跑成功,最终 0 错误行;时间漂移写进局限 |
| J 的 bootstrap 区间随哈希种子变化 | 配对差排序后再抽样,结果固定 |
