# 阶段 0 生死前提 —— manipulation check 结果（2026-08-05）

## 目的

验证 self-model 误校准研究线赖以成立的前提：**frozen 模型能否从"记忆记录卡"里读出可见成功率来调整对自己的估计，且作答前概率不长期饱和在 0/1。** 若模型无视记忆，主实验"只记成功组 vs 随机保留组"无差异，整条线空转。

## 方法（合规 / 可负担）

| 项 | 设定 |
| --- | --- |
| 模型 | 快模型 gpt-5.4-mini（本地代理，开发调试用） |
| 调用纪律 | 串行 + 硬上限 20 次 + 全程缓存（避免高频调用风控风险） |
| 设计 | 4 档可见成功率 × 3 个题面 = 12 次调用 |
| 可见成功率档 | 20% / 50% / 80% / 100%（每档展示 K=10 条记录卡，成功条数 2/5/8/10） |
| 题面 | 两位数加减、一元一次方程、三角形面积（同类、难度相近，让可见成功率成为唯一变量） |
| 卡片顺序 | 固定随机种子打乱，去掉"成功都在前面"的位置线索 |
| 测量 | 作答前问 `p_solve`（0–1），固定 JSON 字段 |

**证据等级标注**：本 pilot 使用**合成的记忆卡**，用途**仅限"测量流程验证"**（对应主方案阶段 0 第 3 步"确认模型能从结果卡读出成功率"）。它**不是主实验、不进主实验结论**。主实验数据契约要求全程零 AI 合成（题目用公开竞赛原题、判分用官方测试／精确匹配、难度用模型真实通过率、历史用被测模型真跑日志）；此处合成卡是显式声明的、限定用途的唯一例外。

## 结果

| 可见成功率 | 题面 1 | 题面 2 | 题面 3 | 档均值 |
| --- | --- | --- | --- | --- |
| 20% | 0.20 | 0.20 | 0.20 | 0.200 |
| 50% | 0.50 | 0.50 | 0.50 | 0.500 |
| 80% | 0.80 | 0.80 | 0.80 | 0.800 |
| 100% | 0.98 | 0.98 | 0.97 | 0.977 |

- **读基率信号**：最高档 − 最低档 = **+0.78**（强、单调）。
- **饱和检查**：12/12 个概率均未落在 0 或 1（不饱和，达标）。

## 判定

**✅ 前提成立（但带黄灯）。**

- **成立**：模型确实读记忆里的可见成功率来调自估 → 主实验"只记成功 vs 随机保留"差异必存在，整线不空转。
- **黄灯**：模型几乎机械地 `p_solve ≈ 可见成功率`（中间档完全线性照抄，仅全成功档轻微收缩到 0.98）。这既是"删失基率"机制方向对的雏形，也暴露了主实验最大的平凡解释——**若主判据停在口头概率，会被视为"复读喂给它的数字"而非"自我认知被扭曲"**。

## 结论对方案的影响

1. **行为式探针（下注／投入精力／真实放弃决策）+ 决策后果**必须从 RQ1 的"备选"升为**主判据**；口头概率降为纯辅助。
2. 需区分"**持久**扭曲自我认知"（frozen + 当场记忆的 substrate 撑不起）与"**当场**依据被删失记忆做偏差估计"（当前 substrate 支持），并据此收紧或升级 headline claim。

## 下一步 manipulation check（未跑）

- **行为式探针**：把"报概率"换成"在做／不做之间下注"，看是否也随可见成功率变——这是主实验命脉。
- **关键删失测试**：当"看得见的成功率"与"真实能力"不一致时，模型跟哪个（直接检验删失基率，需真实历史日志）。
