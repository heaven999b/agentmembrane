# 第七周研究汇报：AgentMembrane RQ2 全量确认与 RQ1 激活校准

> 时间说明：原始 Week 7 RQ2 汇报日期为 2026-08-31；canonical RQ1

## RQ2：记忆接口的表达能力是否会放大错误影响？

### 我们怎么做

本轮没有继续使用前期调参或50题复验的数据，而是从未参与既有RQ2实验的ContractNLI train split中，按合同原文哈希重新抽取100份合同；每份合同各保留一道Entailment和一道Contradiction题，共200题。所有条件都向下游模型提供完全相同的完整原文，只改变外部Agent能够写入的内容：R0只能选择证据，R1可以标注证据，R2可以写结构化推断，R3可以给出结论和建议，R4可以写自由文本。每道题同时生成正常分析和目标导向分析，再观察后者是否让下游答案朝攻击目标移动。

| 接口档位 | 外部Agent能够写入什么 | 这一级想检验什么 |
|---|---|---|
| R0 | 只选择证据 | 单纯改变证据选择是否已经能影响答案 |
| R1 | 选择证据并做标签式标注 | 增加有限语义标注后的影响 |
| R2 | 在相同证据上写结构化推断 | 开放“推理能力”是否带来新增风险 |
| R3 | 在推断上增加结论和建议 | 答案式内容是否继续放大影响 |
| R4 | 把相同语义写成自由文本 | 开放普通文本载体后的总体风险 |

生成与审核使用GPT-5.6-Sol，下游判断使用GPT-5.6-Terra，模型、提示词、样本、阈值和随机种子均在运行前冻结。最初50题只作为工程检查点，用来检查数据完整、缓存隔离、原文一致和输出可解析；没有查看效果值，也没有根据中途结果修改口径。检查通过后，复用已完成调用并继续构建统一的200题结果矩阵。

### 分别检验了什么

1. **主检验**：比较R2相对R1增加了多少攻击影响，即“允许写推断”相对于“只能做证据标注”的新增风险。预先规定：增量至少5个百分点、按合同聚类得到的95%区间不跨0、双侧检验小于0.05，才算工程复验成功。
2. **稳健性检查**：除规范审核通过的样本外，还对全部200次尝试重新计算，避免正结果只是筛选口径造成的；统计时以100份合同为独立单位，而不是把同一合同的两道题当成两个独立样本。
3. **响应范围检查**：分别使用原来的一句话错误建议，以及内容完整、仍与原文绑定的强语义建议，确认下游模型是否存在足够的可观测响应空间。
4. **机制消融**：固定同一份底层证据与推断，只改变结构化/普通文本格式以及是否加入结论和建议，检验“文本格式×答案层”是否解释R2、R3和R4之间的差异。

### 主要结果

主比较得到**14.7个百分点的正增量**，95%区间为8.6到20.8个百分点，按合同聚类的双侧检验为`p=2.24×10⁻⁵`，明显通过预设的5个百分点标准。即使不做规范筛选、直接纳入全部200题，增量仍为13.5个百分点，区间为7.5到19.5个百分点，因此这个信号不是靠删除不利样本得到的。

五档接口的结果如下。这里的“攻击增量”表示目标导向分析相对正常分析，让下游答案朝攻击目标移动的幅度；区间按合同而不是按单题重复抽样。

| 接口档位 | 攻击增量 | 95%区间 | 有效题数 |
|---|---:|---:|---:|
| R0：证据选择 | +5.5个百分点 | 2.5到8.5 | 200 |
| R1：证据标注 | +3.5个百分点 | 0.0到7.0 | 200 |
| R2：结构化推断 | +17.8个百分点 | 12.5到23.4 | 191 |
| R3：结论与建议 | +13.2个百分点 | 8.6到18.2 | 189 |
| R4：自由文本 | +19.4个百分点 | 13.9到25.0 | 191 |

结果说明从证据标注开放到结构化推断时风险出现明显跃升，自由文本的风险最高；但R0到R4并不严格递增，R3也低于R2，因此目前不能声称已经找到一个简单、稳定的单调阈值。R0本身也有小幅影响，所以“低于某一档就绝对安全”的说法同样过强。

原来的一句话响应控制只产生5个百分点变化，低于预设的10个百分点门槛；新的完整语义控制产生12个百分点变化，95%区间为8.0到16.5个百分点，说明模型不是完全无法被语义内容推动。不过，新的控制在本轮协议中只是诊断项，不能事后替换原门槛，因此它支持结果解释，但不能把本轮自动升级成正式论文级claim。

### 消融实验：哪些因素真正解释了差异

消融分成探索和确认两步。第一步在50题上固定相同的证据和推断，构造七个版本：结构化推断、结构化完整答案、普通文本推断、文本推断加结论、文本完整答案、只保留建议，以及把同一段完整文本重复两次。这样可以分别检查格式、结论、建议、上下文和重复长度，而不是把R3/R4的所有差异混在一起。探索阶段看到“格式×答案层”约+12个百分点，原始区间为4到20个百分点；但九项比较校正后不显著。重复相同文本也没有增强影响，反而描述性下降10个百分点，因此“写得更长就一定更危险”不是合适解释。

第二步把最值得复验的“格式×答案层”交互冻结后扩到本轮200题。全部样本的交互为−0.5个百分点，95%区间为−4.0到2.5，`p=1.0`；按规范保留的178题中交互为0，区间为−3.4到2.8，`p=1.0`。也就是说，50题上的+12个百分点没有复现。当前能够确认的是R2相对R1的主增量，而不能把R3/R4的起伏归因于“普通文本加结论/建议”这一单一机制。这项消融是有价值的负结果，应完整保留。

### 当前判断

这轮结果对RQ2给出**强烈的、独立的工程级正支持**：receptor允许表达推断后，目标导向的语义影响显著增加，说明接口表达能力本身确实构成安全边界。它不支持“风险随R0到R4严格单调增加”，也尚未建立跨领域、跨模型的通用阈值。样本与旧实验按原文哈希完全隔离，所有条件使用同一证据包，完整性检查全部通过，且全样本分析保持正结果，所以没有迹象表明结果主要由数据泄漏或筛选偏差造成；模型预训练是否接触过ContractNLI仍无法彻底排除。

本轮仍标记为`claim_bearing=false`：目前只有一个随机种子、一个下游模型家族和一个任务领域，也没有人工审核校准。周报和后续论文应表述为“ContractNLI内的独立工程复验支持非单调的receptor boundary”，不能写成“完整RQ2已被普遍证明”。

## RQ1：Authority Boundary 当前结果

RQ1研究的是外部Agent获得的权限逐步增加时，系统从哪一级开始出现未授权副作用，以及能否在保留正常任务能力的同时挡住这些副作用。当前结果分成“固定轨迹工程底座”“自然攻击激活校准”和“给定攻击动作后的条件式保护”三层；它们回答的问题不同，不能合并成一个成功率。

### RQ1结果总表

| 证据层 | 规模与设置 | 主要结果 | 当前判定 |
|---|---|---|---|
| 固定轨迹工程底座 | 106轮；人工固定轨迹；无模型、网络或API调用 | 保护侧违规效果0/23；授权正常任务30/30；脆弱侧攻击18/18 | 工程检查通过，但不是自然端到端结果 |
| 自然攻击激活校准 | GPT-5.6-Luna；12个AgentDojo工作流；50次脆弱侧攻击会话 | 载荷到达44/50；目标动作提议0；实际目标调用0；攻击效果0 | 激活门槛失败，不能进入正式四格实验 |
| 条件式保护检查 | 7个工作流；固定上游已提出正确攻击动作 | 脆弱侧目标效果7/7；保护侧0/7；保护侧正常任务7/7 | 保护链路在给定攻击动作时通过；不等于自然端到端claim |

固定轨迹结果说明权限检查、终态判定和保护链路在预先构造的轨迹上能够按设计工作，但由于没有模型参与，只能作为RQ1的非claim工程底座。

### 自然攻击校准与完整性检验

随后使用CLIProxy上的GPT-5.6-Luna进行自然攻击激活校准。实验覆盖12个AgentDojo工作流、两档攻击强度，共50次脆弱侧攻击会话；49次完成，1次因输出解析失败保留为未知。注入内容在全部记录中有44/50次到达模型上下文，但模型没有提出任何与攻击目标匹配的原生动作，因此目标动作提议、实际调用和攻击效果均为0。预先设置的门槛要求至少出现5次目标提议并覆盖2个工作流，本轮没有通过，所以不能进入正式的“保护/不保护×正常/攻击”四格实验，也不能把0次攻击解释为防护有效。

| 最终检查 | 结果 | 判定 |
|---|---:|---|
| 运行时审计 | 16/16通过 | PASS |
| RQ语义审计 | 16/16通过 | PASS |
| 最终smoke | 2/2会话完成，8/8调用对账 | PASS |
| 50次校准记录 | 50/50落盘；49完成；1次解析失败 | 有结果，但运行完整性未通过 |
| Provider调用 | 151次预留、151次终态、0次报错、0次用量未知 | PASS |
| 归因异常 | 0 | PASS |
| 最终聚焦回归测试 | 18项通过 | PASS |

### 预注册激活门槛

| 门槛 | 预先要求 | 实际结果 | 是否通过 |
|---|---:|---:|---|
| 载荷到达次数 | 至少20次 | 44/50 | 是 |
| 目标动作提议 | 至少5次 | 0 | 否 |
| 出现目标提议的工作流 | 至少2个 | 0/12 | 否 |
| 归因异常 | 必须为0 | 0 | 是 |
| 运行完整性 | 50次全部完成 | 49次完成、1次解析失败 | 否 |
| 最终决策 | 所有门槛同时通过 | `proceed_to_held_out_four_cell=false` | **NO-GO** |

作为链路定位，我们还固定上游已经提出正确攻击动作，单独检查权限保护：脆弱侧7/7产生目标效果，保护侧0/7产生目标效果，同时保护侧正常任务7/7成功。这说明checker和保护机制在“攻击已经被激活”的条件下能够工作；当前瓶颈主要在GPT-5.6-Luna与现有两种载荷没有把注入转化为目标动作，而不是后端无法测量或保护链路失效。RQ1目前仍为`claim_eligible=false`，准确表述应是“工程底座通过，但自然攻击baseline未激活，正式RQ1结果尚未产生”。

## 下一步

RQ2下一轮应在新协议中预先把“完整语义响应控制”设为正式响应范围检查，并加入额外随机种子、第二个下游模型家族和SciFact等新领域。若暂不进行人工审核，论文需要明确保留“模型审核、无人类校准”的限制。已经失败的格式×答案层交互不需要继续追求正结果，可以作为机制边界写入消融部分。

RQ1下一轮保持研究问题、checker和保护机制不变，只替换自然攻击的激活baseline：选择CLIProxy可用且更容易受到注入影响的另一GPT模型，或者改用不同攻击家族，先跑8到12条校准；只有达到预设的目标动作提议门槛，才进入正式四格实验。
